## Features (current behaviour)
- **Tray icon:** green = nothing unread (temperature with a degree ring), orange = unread news, red = package updates, flashing red ! = scheduled-action warning, pulsing weather alert. Live channels, Read later, orphans and **media never count in the badge**.
- **Popup:** borderless `Gtk.Window`, rebuilt on every manual open, never resized by hand. Its width is `max(WINDOW_WIDTH, what the weather bar needs in either view)` (`_fit_popup_width`, measured on the real widgets, refitted when new weather arrives), placed by that width so the right edge stays against the screen. Closes on focus-out except while the Launch list or a menu popover is open. `refresh_list(keep_open=False)` closes when there is nothing to show; **when only live channels/media remain and the popup is already visible it collapses to "No unread items"** (existing design), so anything that updates while open (download progress, row status) must update labels in place, never call `refresh_list`.
- **News:** left-click opens + marks read, right-click marks read, bookmark icon saves for later; feed header left-click marks the feed read, right-click opens the feed menu (open all as tabs, Website, XML, Categories/Authors with Mute/Later rules written into the feed's line). Feed sections follow config order. Highlight words pulse a row.
- **Weather:** Open-Meteo today + 5-day behind the `›` button; the `‹` back arrow now sits in the **same slot** (right end), so the button stays under the pointer.
- **Live streams:** Twitch (GQL) and YouTube (streamlink + scrape); channel lines are `channel|display name|quality|schedule` (every field after the channel optional; the display name replaces the channel in the "Live now" row and in the player window title `<Site> · <name> · <title>`). Click plays through streamlink into one persistent maximized mpv.
- **Package updates:** scan `xbps-install -Mn -u`; Install all through topgrade with the configured `steps=` (names are topgrade's `--only` ids, lowercase with underscores; `all` allowed), unattended (`--yes --no-retry --no-self-update --skip-notify`, stdin closed, `LC_ALL=C.UTF-8`). `topgrade_env()` also appends `~/.local/bin` and `~/.cargo/bin` to PATH when they exist (a tray started by the session lacks them). The summary block shows `name old -> new` rows (xbps via installed versions before/after, build revision `_1` dropped unless it is all that changed; **Claude Code and rustup** via readers of their step output; Codex/uv print no usable old version and are not read) plus a red `Not updated:` line.
- **Orphans, Timer (countdown + scheduler), Connectivity, Launcher:** as in v4, with one change: **a running countdown survives a restart** (its end is kept as wall-clock `timer_end` in state.json, saved by the 1 s tick; on start the rest is put back on the boot clock; one that ran out while the app was down is a "missed" note, or rings if it ended ≤5 s before start; a bad value is dropped by `load_state`).

## Media (podcasts, series, movies) — built this session
**Sources** are lines in `[media]`: `source|display name|order` (name and order optional; order `oldest` = a series from its first episode, `newest` = a podcast from its latest, default is the driver's). A source is an `archive.org` collection/item URL, a YouTube channel/playlist/video URL, any RSS/Atom feed with audio/video enclosures, `yt-dlp:<url>` for any site yt-dlp reads, `<name>:<anything>` for a plugin, or whatever a plugin's `matches()` takes. Everything DRM-free; Plex (watch.plex.tv) was investigated and is **not supported** (yt-dlp has no extractor, streams likely protected; the app does not circumvent DRM).

**Flow.** Checks (every `interval` minutes, default 60, min 10; on reconnect; at startup) call `driver.list_episodes(source)`, normalize it, `merge_episodes` into `media.json` (first check = baseline: nothing announced; a `newest` source marks all but the latest watched). New episodes call `on_new_items()` (sound, popup opens, like a channel going live). The downloader keeps the next `ahead` (default 2; 0 = only on click) unwatched episodes on disk, one download at a time, into `path` (default `~/videos`) as `<Source>/<Source> - S01E05 - <Title>.<ext>` (+ `<name>.<lang>.<ext>` subtitles beside it, which mpv loads on its own). The popup's **Media** section has one row per source: `● Name - S01E05 Title - ready|43%|queued|failed|not downloaded - 2 new` (marker green/amber/red/grey, tooltip with unwatched count, last watched, the reason for a failure). Click = play next unwatched in the shared mpv (or start/prioritise its download). **Watched** = mpv, polled over IPC every 2 s, reached 90 % or (≥ 50 % and ≤ 20 s left). A source that cannot be read shows a red row ("cannot be read", reason in the tooltip, click retries).

**Drivers and plugins** (`mediasources.py`): interface = `list_episodes(source) -> (title, [episode])` (required, oldest first), `matches(source)`, `resolve(episode)`, `download(episode, base, progress, cancelled)`, `NAME`, `ORDER`. Built-ins (archive, yt-dlp for YouTube, feed) use the same interface; **plugins** are `*.py` files in `~/.config/void-tray/media-plugins/`, reloaded at every check when their mtime changes, asked before the built-ins (so one can take over a site), selectable by a `name:` prefix. Everything a driver returns is checked by `normalize_episodes` / `normalize_files` / `normalize_saved` (string unique ids, `YYYY-MM-DD` dates, whole-number `season`/`episode`, extensions, `headers`, subs). An episode's `url` is a **file**; the page it came from goes in `ref`. Episodes remember their `driver`; episodes stored before drivers existed are read by `kind`. `README.md` "Media plugins" is the contract; keep it in step with the code.
- `season`/`episode` ints given by a driver are kept (else read from `S01E05`/`1x05` in the title); `clean_title` strips the series name and number from titles; ties keep the driver's oldest-first order (`order_episodes`).
- archive.org: collection = search API (items are episodes, files looked up lazily at download), item = one episode per media file (versions grouped by `original`/suffix; h.264 derivative preferred). Shapes come from three documentation sources; **never verified against the live site**.
- **yt-dlp driver:** `--flat-playlist --dump-single-json --extractor-args youtubetab:approximate_date`; a channel's Podcasts tab (a list of shows) has each show opened (max 10); channel tabs are reversed to oldest-first; private/live/upcoming skipped. Downloads: one yt-dlp run per episode, `--write-subs --sub-langs en.*,-live_chat`, `-S res:<screen height>` (1080 if unknown), `ytdlp=` config args come later and win. **`--print` makes yt-dlp quiet and hides progress unless `--progress` is given**; the progress template carries the file name so a subtitle's own 100 % is skipped. Verified with the real binary against a local page only.
- **HLS** (`hls.py`): a video url ending `.m3u8` is downloaded by `download_hls` from the default pipeline, no plugin code needed: master playlist → `pick_variant(variants, screen)`; length from the playlist's `#EXTINF` sum (ffprobe fails on some servers) so progress is a real percent; ffmpeg `-c copy` (no audio re-encode) into `.mkv` (default) / `.ts` / `.mp4` as `dest.part`, renamed when complete; reader thread drains ffmpeg's output (**a reader that does not drain stalls ffmpeg**: measured), 120 s stall timer, cancel kills ffmpeg, failure leaves nothing (HLS cannot resume), a live playlist is refused. `headers` on the video/each subtitle (Referer, User-Agent) are sent to playlists, segments and ffmpeg. A failing subtitle never fails the episode.
- **Screen-aware size** (last change): `pick_variant` takes the best variant that fits the screen as a player shows it (`max(w/screen_w, h/screen_h) <= 1.15`; 1440x720 fits 1366x768, 1920x1080 does not); none fits → the smallest; sizes unknown or no screen → most bandwidth. yt-dlp gets `-S res:<screen height>`. The monitor is read on the main thread (`desktop.primary_monitor_size`, at its scale factor) at start and on `monitors-changed` and kept in `screen.py` for the worker threads; `screen=WxH` in `[media]` overrides it.
- **Watch while downloading:** an HLS download to `.ts`/`.mkv` publishes `part` (path) and `length` (playlist seconds) in `media_status`; once 1.5 MB has arrived a click plays the `.part` file (mpv keeps playing across the final rename). Because mpv's own duration of a growing file is an estimate, the watcher measures `time-pos` against the playlist length; without a length it plays untracked. `.mp4` and plain downloads cannot be watched early.
- **Config watcher:** `config.conf` is monitored (Gio, 800 ms debounce); new `[media]` sources are checked **on their own immediately** (`start_media_check(only=...)`: a full check is skipped while one runs, a check of given sources is queued behind it, decided under `_media_request_lock`); renames/order/`ahead` edits update rows in place with no check. The user's Firefox extension appends lines this way.

## Conventions and gotchas
- Locks: `lock` (state), `_check_lock`, `_xbps_lock`, `_twitch_lock`, `_youtube_lock`, `_player_lock`, `_mpv_lock`, `_media_data_lock`, `_media_queue_lock`, `_media_request_lock`. Never block the GTK thread on network or subprocesses; plugin code runs in worker threads and **a plugin that hangs stops every media check** (document timeouts).
- CSS in `POPUP_CSS`: one unknown property drops the whole stylesheet (check the log for "Failed to apply CSS styles"); the list is white so custom labels need dark text. A `Gtk.Popover` cannot leave its window. `set_no_show_all` blocks `show_all` on that widget.
- Pitfalls found this session: `Path.with_suffix` replaces everything after the last dot, so `Dr. House - S01E01 - Pilot` became `Dr.ts` (always build paths by string concatenation; the contract says `base` + extension); `feedparser` resolves a relative `guid` against the feed URL; JSON object keys become strings; `out_time_ms` in ffmpeg `-progress` is microseconds; ffprobe can fail on a stream ffmpeg downloads fine; a `Gio.FileMonitor` must be kept referenced; `Gdk` is main-thread only (workers read `screen.media_target_size()`).
- **Persistence (v6):** `state.py` saves through `_write_json` (a unique `<name>.<hex>.tmp` created exclusively in the same directory, removed on failure). A `state.json`/`media.json` that is not valid JSON, not text, or not the expected shape (an object; for media.json an object whose `sources` is an object) is moved to `<name>.corrupt` by `_set_aside` before the empty default is used (one copy, a later corrupt file replaces it, logged with `_log`); a file that raises `OSError` on read is left alone and a missing or `{}` media.json is normal. `config.py`'s `_edit_config_section` still writes a fixed `config.conf.tmp` (see open items).
- **Network (v6):** `_dns_ok` keeps at most one lookup thread in flight (`_dns_lookup` under `_dns_lock`; a probe that finds it alive joins it, one that finds it ended starts a new one). `run_when_online` appends to `_online_waiting` and one `_wait_for_network` poller serves every caller (each callback on its own thread; a probe that raises is logged and retried, the poller never dies). Tests that touch these reset the module state with `mock.patch.object(rt, '_dns_lookup', None)` / `_online_waiting` / `_online_poller_running`, or a thread left by an earlier test leaks into the next.
- Thread tests: never release a blocked worker until the other side is provably waiting (a first version of a "probes at the same time share one lookup" test released too early and failed one run in eight); use a `threading.Timer` with a generous margin, or a sequential test.
- Mock-heavy UI tests are brittle: most failures after feature work are stub fixtures (stubs borrow real methods: `class Stub: method = rt.RssTray.method`). New logic gets pure tests; UI gets a few behaviour tests plus a real-GTK run.

## Decisions, standing behaviour, open items
- Standing choices: opening an item (or all of a feed) counts as read; saved items are not unread and never in the badge; a mute rule beats a read-later rule; a missed countdown does not ring late; media rows never hold the popup open and update in place; a downloaded file is only "ready" after it is recorded (`.part` until complete); watching a partial file is tracked only against a known playlist length; a podcast starts at its latest episode; nothing is deleted when an episode is watched.
- **Done in v6:** the four small fixes from the second AI's refactoring brief (corrupt state files set aside, unique save temp names, one shared DNS lookup and online poller, a facade that fails on name clashes). The rest of that brief was reviewed and is already handled or is churn the user does not need (service objects, splitting `ui/feeds.py`, Ruff, typed config). Ask before starting any larger refactor.
